# 한글 픽셀 폰트

원작 HUD는 `src/70-pixelfont.js`의 `PX`가 직접 정의한 7픽셀 높이 비트맵 글꼴로 그린다(라틴 문자만). 한글 11,172자를 손으로 찍을 수는 없고, 웹폰트·시스템 폰트는 "에셋 0개·픽셀 감성" 원칙과 헤드리스 검증의 결정성을 깬다. 그래서 **빌드 시점에 실제로 쓰는 글자만 비트맵으로 뽑아 번들에 넣는다.**

## 파이프라인

```
src/*.js, src/shell.html ──(한글·기호 스캔)──▶ tools/hangul.py ──▶ src/71-hangul-data.js (자동 생성)
                                                   ▲
                               /usr/share/fonts/opentype/unifont/unifont.otf (16×16 비트맵 글꼴)
```

1. `tools/hangul.py`가 `src/` 전체에서 ASCII가 아닌 문자를 모은다(주석 포함해도 무방, 수백 자 수준).
2. Pillow로 Unifont 16px을 `ImageFont.truetype(path, 16)`로 래스터화한다. Unifont는 16px에서 정확히 픽셀 격자에 맞는 1비트 글꼴이라 안티앨리어싱 없이(`mode '1'` 또는 임계값 128) 깨끗하게 나온다.
3. 글자마다 `폭(8 또는 16) + 16행 비트맵`을 압축 문자열로 내보낸다(행당 16비트 → 4 hex, 글자당 64 hex). 400자면 약 26KB.
4. `tools/build.py`가 빌드 첫 단계로 `hangul.py`를 호출한다. 글꼴 파일이 없는 환경(사용자 PC)에서는 **기존 `71-hangul-data.js`를 그대로 쓰고 경고만** 낸다 — 그래서 생성물은 저장소에 커밋한다. 생성물에 없는 글자가 소스에 있으면 빌드가 그 글자 목록을 경고로 출력한다.

Unifont는 SIL OFL 1.1 / GPLv2+(폰트 예외) 이중 라이선스다. `vendor/LICENSE-unifont.txt`에 고지를 넣고 README에 적는다.

## PX 확장 설계

원작 API(`PX.measure(str)`, `PX.text(ctx, str, x, y, scale, color …)`, `PX.LINE`, `PX.CAP`)의 **시그니처는 그대로** 둔다 — `72-ui.js`의 레이아웃 계산이 전부 여기에 묶여 있다. 실제 시그니처는 `70-pixelfont.js`를 읽고 확인한다.

핵심 결정은 **7px 라틴과 16px 한글의 높이 차**를 어떻게 다루느냐다.

- 권장: 문자열에 한글이 하나라도 있으면 그 **문자열 전체를 16px 글꼴 격자로** 그린다(라틴·숫자도 Unifont의 8×16 반각). 한 문자열 안에서 두 글꼴이 섞이면 기준선이 들쭉날쭉해 보인다.
- 16px 문자열은 HUD 스케일 `s`의 **절반 스케일**(`s/2`, 최소 1)로 그려 7px 라틴 줄(`LINE=9`)과 비슷한 실제 높이(8px 상당)를 맞춘다. `s`가 홀수면 `Math.max(1, Math.round(s/2))`로 정수 배율을 유지한다(비정수 배율은 픽셀이 뭉개진다).
- 그 결과 `measure()`는 "라틴 픽셀 단위"로 환산한 폭을 돌려줘야 `72-ui.js`의 판 크기 계산이 맞는다. 환산 계수를 한 곳(`PX` 내부)에 둔다.
- 숫자만 있는 문자열(군자금 `300`, `1x`)은 원래 7px 글꼴 그대로 — 가장 자주 바뀌는 HUD 숫자의 또렷함을 지킨다.
- 줄바꿈(`wrap`)은 한글이 어절 단위로 끊기도록 공백 기준을 유지하되, 한 어절이 줄 폭보다 길면 글자 단위로 끊는다.

글리프 캐시(`CACHE_MAX`)와 색 입히기 방식은 원작 구현을 따른다. 한글 글리프도 같은 캐시에 `'h:' + 문자열` 키로 넣는다.

## 문구 작성 규칙

- 설계서 §6 용어집을 그대로 쓴다. 새 문구는 14~18자 이내, 마침표 없는 명사형/평서형.
- 모바일 세로(390px 폭)에서 한 줄에 들어가는지 스크린샷으로 확인한다.
- 조사 자동 처리(을/를)가 필요한 조합 문구는 피하고, "새 적: 중갑병"처럼 콜론 구조로 쓴다.

## 검증

```bash
python3 tools/build.py
node tools/cdp.js "seed=4&ff=20" 1280,800 wait:4000 shot:ui-desktop
MOBILE=1 DPR=2 node tools/cdp.js "seed=4&ff=20" 390,844 wait:3000 shot:ui-phone
```
스크린샷에서 □/?/빈칸이 없어야 하고, 판 테두리 밖으로 글자가 넘치지 않아야 한다. `grep -c "[A-Za-z]\{4,\} [a-z]\{3,\}" src/72-ui.js`로 남은 영어 문장을 찾는다(키 이름 `'Escape'`, `'Enter'` 등 입력 코드는 번역 대상이 아니다).
