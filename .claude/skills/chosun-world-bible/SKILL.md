# 조선워치 세계관 계약

Cinderwatch(다크 판타지 타워 디펜스)를 한국사의 네 전쟁 — 고구려·수, 고구려·당, 고려·몽골, 조선·일본 — 으로 옮기는 작업의 **단일 진실 원천**이다. 여러 에이전트가 따로 만든 지형·적군·타워·UI·소리가 한 작품으로 보이려면 같은 표를 봐야 한다.

## 읽는 순서

1. `references/world-bible.md` — 전체 설계서. 자기 담당 절(§)과 §0~§3, §8은 반드시 읽는다.
2. `src/05-lore.js` — 코드로 박힌 계약: `ERA`, `ARMY` 색, `curEra()`, `curArmy()`, `monName()`, `towerName()` 등.
3. `src/29-biome.js` — 전장별 `era`, `army`, `year`, `title`, `lore` 필드.

## 세 가지 불변식

왜 지켜야 하는지까지 이해하고 작업한다.

1. **내부 키와 수치는 그대로.** `MON`·`TOWER`·`BIOMES`의 키, 능력 필드, 밸런스 수치는 웨이브 생성기와 AI 군사, 저장 기록이 직접 참조한다. 이름과 겉모습만 바꾸면 원작이 다듬어 놓은 난이도 곡선을 공짜로 물려받는다.
2. **색은 `ERA`/`ARMY`에서.** 깃발·군복·장식색을 각자 고르면 전장마다 "어느 군대인지"가 흐려진다. `C(ERA[curEra()].main)`처럼 표에서 가져온다.
3. **에셋 0개, 단일 HTML.** 이미지·폰트·오디오 파일과 네트워크 요청을 추가하지 않는다. 원작의 핵심 매력이고, `file://`로 열려야 하며, GitHub Pages 배포가 파일 하나로 끝난다.

## 고증이 불확실할 때

- 통설과 다른 주장, 야사는 문구에 쓰지 않는다. 필요하면 "전한다"로 표기.
- 새 고유명사(장수·무기·지명)를 넣기 전에 `lore-historian` 검수 결과(`_workspace/01_lore_review.md`)에 있는지 확인하고, 없으면 `_workspace/handoff/`에 질문을 남긴다.
- 표와 코드가 어긋나면 코드의 키를 따르고, 표를 고쳐 달라고 보고한다.

## 설계서를 고칠 때

설계서 변경은 오케스트레이터(또는 `lore-historian`)만 한다. 다른 에이전트는 `_workspace/handoff/{자기이름}-to-bible.md`에 "무엇을 왜 바꿔야 하는지"를 적는다. 표 하나를 고치면 영향받는 에이전트(§의 담당자)를 다시 돌려야 하기 때문이다.
